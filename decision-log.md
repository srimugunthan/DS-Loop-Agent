| 36 | API key handling and API access: LLM gateway | **An LLM gateway is built in Phase 1** (revised; originally deferred to Phase 2). It is a small custom FastAPI container (about 150 lines, no database) that holds the API key, read from a git-ignored `.env` outside every workspace. Agent containers have no internet access and no real key: their SDK points at `ANTHROPIC_BASE_URL=http://gateway:8080/exp/<experiment-id>` with a placeholder key. The gateway forwards only model requests to `api.anthropic.com`, streams replies through unbuffered, reads token usage from each reply, prices it, records tokens and cost per experiment in the experiment record, and refuses requests once the loop's dollar cap (decision 35) is reached. In dev mode it runs as a local process. Kept precautions: a demo-only key with a monthly spend limit set in the Anthropic Console, and masking of anything matching `sk-ant-…` in logs. Chosen over the key in the agent container (the original answer) and over LiteLLM proxy (budgets per key rather than per experiment, needs a database). The same gateway serves Phase 2 coworkers | Grilled Q20 (round 3), revised by user after the gateway effort/cost follow-up | [ADR-007](docs/adr/ADR-007-llm-gateway-holds-api-key-and-meters-cost.md) |

| 46 | Post-modelling analysis stage | A new stage, **post-modelling-analysis** (agent: `post-modelling-analysis-agent`), between model-training-eval and model-summary; chat mode only. **The platform computes the numbers** in the check runner: per-segment metrics for the spec's segments, SHAP global importance and dependence, calibration (classification) or residuals (regression) by segment, importance stability across CV folds. The agent chooses extra cuts and interprets results, but never produces numbers. SHAP and importance stability are computed on the training data's CV folds. Held-out results use only what the stage 3 gate saved (predictions, targets and the spec's segment columns for held-out rows, in a platform-owned folder), so the held-out set is never re-read and the counter stays at 1; the agent sees aggregates only, never held-out rows. Checks: every spec segment covered; every number matches a computed result; red flags (an ID or forbidden column among top features, one dominant feature, a segment beyond tolerance, unstable importances across folds). Outcomes: approve, or "reopen stage 2/3 with these findings" (stale handling, decision 30). Stage 3's blocking segment check stays. New: `ds-analysis` skill; SHAP in the check-runner image | Grilled Q31 (round 4) | — |
| 47 | Hyperparameter tuning placement | Tuning stays **inside stage 3** (no dedicated stage). Then the held-out gate, once. One approval. The timeline and chart show the switch from explore to refine | Grilled Q30 (round 4) | — |
